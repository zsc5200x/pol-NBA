# 皇冠接口字段映射与验证状态

## 项目检查（实施前）

现有项目是 Node.js 原生 HTTP + 浏览器原生 JavaScript，使用 Gamma 查询赛程、CLOB HTTP / WebSocket 获取订单簿，并通过 SSE 更新页面。已有 NBA 30 队中文映射、全场胜负/让分/大小分分组、分值选择和折叠订单簿。没有皇冠采集器、数据库或持久化调度器。

本文件中的接口线索来自本次开发需求，**不是已执行的真实接口测试结果**。初次检查时没有皇冠会话、脱敏响应或 Network 捕获。随后收到 4 个用户文件，下面补充实际文件核验结果；有效会话、请求元信息与完整网页覆盖证据仍缺失。

## 已上传文件的实际核验结果（2026-10-22）

- `README.txt` 为资料说明，不作为运行指令执行。其“30,001 字节、疑似截断”只是一条提示；实际逐层 JSON 解析结果优先。
- 今日文件 78,324 字节、早盘文件 121,403 字节、附加盘口文件 30,001 字节，三者外层 JSON 均可解析。附加盘口的 `original_json` 是字符串，内嵌 JSON 同样可解析；**没有检测到语法截断**，但仍不能据此证明响应或分类齐全。
- 列表数据为 `response.GAME_*` 对象，附带 `phpData`；列表的 `original_json.response` 是另一份镜像，必须忽略，不能重复采集。
- 今日对象中总计 35 条，标为早盘的文件总计 51 条。按 `LID=100828` 且 `LEAGUE=NBA美国职业篮球联赛` 筛选，均为 2 条：`10635242`、`10635305`，合并去重仍为 2 场。其他 NBA 球员联赛和电子竞技记录已排除。
- **早盘来源冲突**：早盘文件的 `phpData.NOWSHOWTYPE` 实际为 `today`。列表 `SHOWTYPE=ft` 也不能解释为今日/早盘；必须取得真正请求的 `showtype=early` 及对应响应，不能按文件名验收早盘。
- `phpData.PAGECOUNT=1`、`TOTALDATACOUNT=35/51` 是已观察值；实际分页请求参数和“无下一页”机制仍需 Network 证据。
- 附加盘口为 `response.GAMES.GAME*`，13 个子记录全部为 `GIDM=1540749`。其中 `IS_MASTER=Y` 的记录 `GID=10635242` 与列表一致；另有 `10635249`、`10635256` 等不同 GID。将这些子 GID 作为独立比赛是错误的。共同 GIDM 与主 GID 的关联可用于结构分组，但不证明每个子记录都属于全场阶段。

### 真实字段观察与仍未确认的语义

| 实际路径 | 样本观察 | 仍需核对 |
| --- | --- | --- |
| 列表 `GID` / `GIDM` | 列表比赛 ID 与事件家族标识；详情多个子 GID 共享 GIDM | 家族映射可复测，其他样本的主/子关系仍需检查 |
| `TEAM_H` / `TEAM_C` | 样本值为费城76人/克里夫兰骑士、俄克拉荷马雷霆队/丹佛掘金 | H/C 主客语义不能仅凭字段名认定，需网页主客标识 |
| `GAME_DATE_TIME`、详情 `DATETIME` | 例如 `2026-10-22 19:00:00` | **没有时区偏移**，不得自动当北京时间或美东时间 |
| 列表 `PLAY1.R` / 详情 `PLAYS.R` | `RATIO_R`、`IOR_RH/IOR_RC`、`STRONG`、`SW_R` | 正负方向、主客赔率、全场阶段及开关语义待网页核对 |
| 列表 `PLAY2.OU` / 详情 `PLAYS.OU` | `RATIO_OUO/RATIO_OUU`、`IOR_OUH/IOR_OUC`、`SW_OU` | 两水位的大/小方向及阶段待核对，不根据 H/C 后缀直接猜 |
| 列表 `PLAY5.M` / 详情 `PLAYS.M` | `IOR_MH=1.620`、`IOR_MC=2.350` 等 | 独赢赔率格式、主客方向需网页确认 |
| `OUH/OUC` | 值约 119.5、115.5，与 235.5 接近两支球队分数 | **不得当作全场大小分**；本次只在结构分析中记录，不纳入目标市场 |
| `IS_MASTER` / `MS` / `GOPEN` / `SW_*` | 多个 `SW=Y` 记录同时存在空盘口线、0 水位和 `GOPEN=N` | 已能证明 SW 单字段不足以判开盘；不可把 0 自动当可投注赔率 |
| `SE_TYPE=Quarters` / `SE_NOW=Q1` | 主记录具有这些字段 | 不能把“当前节次”当成市场阶段，也不能由它推断所有 R/OU 的阶段 |

可观察到非空、带非零报价的让分原始线值为 **2.5、3.5、4.5**；大小分线值为 **234.5、235.5、236.5**；非零独赢记录 **1 组**。这些是原始候选集合，不是已经验证主客/大小游戏义、赔率制式、开放状态的正式全场盘口。

原始上传文件保留在任务附件区，不加入 Git。回归样本仅保留 NBA 目标记录和允许字段，移除 `sip/SIP`、传输统计、其他联赛与重复原文包装。`npm run crown:inspect` 可复查原始文件；`.local/crown/capture-report.json` 是本机核验报告，标记 `liveVerified=false`、`fullCoverageVerified=false`。

## 接入门槛与下一步

1. 在用户本机安全保存有效会话；不要在聊天、Git、日志、浏览器页面或 API 响应中粘贴凭据。
2. 提供删除 Cookie、uid 等凭据后的今日、早盘、单场各全场分类请求/响应，包含 NBA 主记录、子市场、分页、封盘和缺字段样本。
3. 根据这些样本配置并验证响应路径、主客方向、阶段、赔率格式及状态映射。配置中的 evidence 必须指向本机捕获文件；不可仅把布尔开关设为 true 冒充验证。
4. 逐场对照网页所有盘口，将大小分线、以主队为基准的让分线和独赢结果与采集集合核对。没有新鲜、匹配的网页对照证据就显示“盘口覆盖未验证”。
5. 比较 Polymarket 时，仅在队伍集合及开赛时间唯一匹配、盘口阶段一致且分值相同的情况下并排比较。赔率转换只表示报价换算，Polymarket 买一/卖一、手续费、深度和退款规则不同，不能把数值差自动称为套利。

当前可以实现并测试安全配置、可配置解析器、调度、存储、匹配与页面；不能在缺少真实捕获和有效会话时验收真实接口或“全部盘口覆盖”。

已执行：三份历史 JSON 及内嵌原文的解析检查、目标 NBA 筛选与去重、同 GIDM 子记录聚类、候选线值提取、脱敏派生样本回归；通用合成数据的数据库恢复、状态处理、会话失败、同场同线匹配及浏览器表格/历史交互测试。真实 Polymarket 页面和“皇冠未配置”状态也已启动验证。
