# 皇冠接口字段映射与验证状态

## 当前接入范围

2026-10-22 已通过本项目保存的有效会话，从终端请求今日 NBA 列表、早盘 NBA 列表，以及两个模式的 `get_game_more` 详情。此次列表返回今日 2 场、早盘 12 场，共 14 个主比赛 ID；这是该次查询的数量，会随赛程变化。

目标是将皇冠的全场独赢、让分及大小分，按同场、同分值、同球队或大/小方向显示在 Polymarket 报价下面。`Main` 响应内的附加全场让分和总分也会解析；半场、单节、球队总分及其他玩法不混入全场比较。没有对应分值、封盘、零水位、请求失败或数据过期时，不显示有效水位。

## 已验证的请求

运行时使用本项目加密保存的会话，Cookie、UID、版本参数不进入 Git、页面或日志。当前项目会话对应的固定来源由 `src/crown/config.mjs` 的 `ENDPOINT` 决定；用户曾提供的其他来源上的旧 UID 不直接复用。

| 用途 | POST 表单关键字段 |
| --- | --- |
| 今日列表 | `p=get_game_list, gtype=bk, showtype=today, ltype=3, rtype=r, filter=MIX` |
| 早盘列表 | `p=get_game_list, gtype=bk, showtype=early, ltype=3, rtype=r, filter=FU, date=all, lid=100828, action=click_league` |
| 今日详情 | `p=get_game_more, gtype=bk, showtype=today, ltype=3, lid=100828, gid=<列表主GID>, type=getMore, from=game_more, mode=NORMAL, filter=Main` |

## 详情归属、阶段与字段

详情容器为 `response.GAMES.*`。列表主 `GID` 是比赛 ID，`GIDM` 是同场家族标识。附加盘口可以有不同子 GID，不能作为新比赛计数。

| 标准含义 | 真实字段与规则 |
| --- | --- |
| 球队 | `TEAM_H` 对应 home，`TEAM_C` 对应 away；匹配时按球队身份，不按两平台展示顺序 |
| 全场让分/总分归属 | 详情 `GIDM` 等于列表 `familyId`，且 `MS` 必须是明确的空字符串；缺失 MS 不等于空字符串 |
| 全场独赢 | 主 GID 且 `IS_MASTER=Y`，避免附加记录的关闭独赢覆盖主盘 |
| 让分幅度与方向 | `PLAYS.R.RATIO_R` 为非负幅度；`STRONG=H` 主队让分，主队线为负；`STRONG=C` 客队让分，主队线为正；客队线取相反数 |
| 让分水位 | home=`PLAYS.R.IOR_RH`，away=`PLAYS.R.IOR_RC`，香港盘 |
| 总分线 | `PLAYS.OU.RATIO_OUO` 与 `RATIO_OUU` 必须相同 |
| 总分水位 | 大分=`PLAYS.OU.IOR_OUC`，小分=`PLAYS.OU.IOR_OUH`，香港盘；不可按 H/C 字母猜大/小 |
| 独赢赔率 | home=`PLAYS.M.IOR_MH`，away=`PLAYS.M.IOR_MC`，十进制赔率 |
| 开放状态 | 同时核对记录 `GOPEN` 和盘口 `SW_R/SW_OU/SW_M`；关闭或未知状态不得显示有效报价 |

`MS=主GID_1` 等带阶段后缀的记录不进入全场比较。`OUH/OUC` 是另一组玩法，不能用来补全全场大小分。`SE_NOW=Q1` 是赛事字段，不能代替盘口阶段判定。

空线、零水位且记录已关闭的附加占位可以跳过；开放记录缺线、方向未知、总分两边不同等仍按解析问题处理。让分统一保存为皇冠 home 的带符号分值，再与 Polymarket 同线比较。不会把 `+4.5` 与 `-4.5` 或相邻分值混配。

## 当前报价与历史快照

每场详情完成后，将此次实际返回的目标盘口键作为当前集合。旧盘口继续保存在 SQLite 历史中，但从最新响应消失、换线或换方向的旧键不再用于当前比较。正常轮询等待期间，上一轮仍新鲜的水位可继续展示；已确认请求失败的场次立即退出有效比较。重启后须完成新一轮详情验证，才会启用缓存盘口。

本机配置对无时区开赛时间采用 `America/New_York`，并保留独立时区核对证据；匹配使用 ISO 时间，页面按 `Asia/Shanghai` 显示。球队及开赛时间必须唯一对应，盘口类型和分值必须完全一致。

## 验收边界

此次完成的是当前已捕获 `Main` 响应的全场目标盘口解析和同线展示。成功采集场次数不代表逐场所有分类已覆盖；`coverage` 仍要求独立、未过期的网页线集合证据，不能因为解析成功就改为“全部已核对”。不枚举没有证据的 filter，不把历史样本当成实时水位。

早期上传的一份“早盘”文件内部 `NOWSHOWTYPE` 实为 `today`，该历史样本仍由 `crown:inspect` 标记来源冲突。后续已用真实 `showtype=early` 请求验证早盘，这两类证据应分开理解。
