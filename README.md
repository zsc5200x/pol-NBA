# COURTSIDE · Polymarket NBA 盘口监控

只读网页程序，追踪 Polymarket NBA 比赛的胜负、让分、大小分市场，展示每个结果的买一/卖一、中间价、价差和订单簿深度。无需钱包、API Key 或交易授权。

## 启动

需要 Node.js 22.13 或以上版本（本云环境已验证 Node.js 24）。

### 下载到自己的电脑

1. 安装 [Node.js](https://nodejs.org/) 的 LTS 版本；安装时保留默认选项。
2. 打开 [GitHub 仓库](https://github.com/zsc5200x/pol-NBA)，点击绿色 **Code** 按钮，再点击 **Download ZIP**。
3. 解压 ZIP 文件。使用 VS Code 打开解压后的项目文件夹（其中应能看到 `package.json`）。
4. 在 VS Code 菜单中选择 **终端 → 新建终端**，依次执行：

```bash
npm ci
npm start
```

5. 保持终端窗口打开，在自己电脑的浏览器地址栏输入 `http://localhost:3000`，即可查看页面。

修改界面主要编辑 `public/` 下的文件，然后刷新浏览器。修改行情处理或服务代码后，在终端按 Ctrl+C 停止，再执行 `npm start`。这个项目没有前端热更新服务。默认使用真实行情；需要纯模拟数据时先停止服务，再执行 `npm run demo`。

熟悉 Git 的用户也可以通过终端下载：

```bash
git clone https://github.com/zsc5200x/pol-NBA.git
cd pol-NBA
npm ci
npm start
```

### 云环境启动

```bash
cd /workspace/pol-NBA
npm ci --ignore-scripts --cache /workspace/.cache/npm
npm start
```

默认监听本机 `127.0.0.1` 的 `3000` 端口。在自己的机器上启动后，使用浏览器访问该端口。`PORT=3001 npm start` 可以更换端口。只有需要让其他机器访问时才设置 `HOST`；程序是本地开发工具，没有多用户认证。

```bash
npm run demo   # 明确标记的模拟行情，与真实模式分开启动
npm test       # 离线单元测试与本地 HTTP / SSE 集成测试
npm run check  # JavaScript 语法检查
```

演示模式需要停止原服务或使用不同的 `PORT`。连接失败不会自动切换到演示数据。

## 使用

1. 选择日期范围和时区。默认上海时区的**今天及未来两天**；“过去 3 天”包括今天及此前两天；“前后各 2 天”共五个自然日。
2. 在左侧选择比赛，在中间选择盘口及结果；右侧显示所选结果的深度。
3. 买入价 Ask 是卖方最优挂单，卖出价 Bid 是买方最优挂单。价格以美分显示；份额是合约数量，累计金额为各档价格乘份额的总和，以 USDC 名义金额显示。
4. 每侧展示最优 12 档的数量、累计数量、累计金额和深度条；总挂单金额统计当前结果订单簿全部档位，不保证成交。

让分和总分的多个线位分别显示，不会把不同线位的订单混合。NBA 球员数据盘口、半场盘口暂不纳入首版。

胜负、让分、大小分现在分别合并为一张盘口卡片。让分和大小分通过卡片内的横向分值栏切换；让分分值以对阵中的第一支球队为基准，正负号分别表示受让和让分。卡片并排显示双方买入价（卖一），点击结果会在该卡片内展开对应订单簿。切换分值时保留所选球队或大/小方向，行情推送不会重置分值选择，不同市场的订单簿仍按原始标的独立处理。

订单簿默认收起，各盘口的分值栏始终可见。点击报价或“展开订单簿”打开深度，再次点击同一报价或“收起订单簿”即可关闭；同一时间只展开一个盘口。收起时切换分值只更新报价，不会自动展开，实时行情更新也不会改变展开状态。深度默认每侧 6 档，可切换为 12 档；实时更新时保留页面与市场盘口内容区的滚动位置。切换比赛时恢复收起状态。展开订单簿时，市场盘口容器保持高度，超出的内容统一在容器内部上下滚动；桌面并排面板保持底部对齐。

### 让分、大小分价格历史

桌面页面在紧凑盘口区右侧显示“价格变动”，分别展示 Pol 和皇冠的双方报价、涨跌差值、盘口分值和变化时间。选择比赛后可切换让分／大小分以及具体线位；两个平台分别读取最近记录，也可翻看更早的记录。胜负盘保持当前报价，不加入新的价格历史。

后端自动记录当前监控范围内让分、大小分的 Pol 买一／卖一变化，以及成功对应到同场同线的皇冠水位变化。首次采集记为基准，价格相同、挂单数量变化及心跳刷新不会重复记作价格涨跌。暂停、过期、恢复报价单独标注；无报价以空值保存，不按零价格计算跌幅。数据在本机 `.local/price-history.sqlite` 中持久保存，可用 `PRICE_HISTORY_DB_PATH` 指定位置。关闭网页不影响后台采集，退出程序或电脑休眠期间无法记录；重启后的第一条重新建立基准。

历史从启用记录后开始积累，不回填之前未采集的 Pol 价格。皇冠为轮询快照，只能记录每次请求时看到的水位，不能重建两次采集之间的短暂跳价；表中时间是本项目观察到报价的时间，并按页面时区显示。原皇冠快照数据库继续保留。两种数据库均已忽略，不会随 Git 上传。

`GET /api/price-history?eventId=...&marketId=...&type=spreads&source=pol&limit=50` 查询同一盘口记录；`type` 支持 `spreads`／`totals`，`source` 可选 `pol`／`crown`，`before` 使用上页返回的 `nextBefore` 游标。记录按最新优先返回，每页最多 200 条；接口仅供本机同源访问。历史保存的是最优报价，不包含完整订单簿回放。

页面将 30 支球队、比赛对阵、胜负、让分、大小分结果及连接提示统一映射为中文，原始市场标识、价格与份额保持不变。让分结果标明双方各自的正负分值，大小分结果带具体总分线。球队图标随项目保存在 `public/logos/`，浏览器无需访问外部图片网站；图片加载失败时显示中文队名标记。图标来源说明见 [public/logos/NOTICE.md](public/logos/NOTICE.md)。

从 ZIP 更新时，先在旧服务终端按 Ctrl+C 停止，备份旧文件夹，再下载并解压新版，在新文件夹内执行 `npm ci` 和 `npm start`。不要直接覆盖自己已经修改的文件。

## 行情更新

- Gamma `/sports` 动态发现 NBA 赛季，通过 `/events/keyset` 查询、分页并每分钟刷新赛程。按比赛开赛时间和所选时区过滤，不使用市场创建时间。
- CLOB `/books` 获取完整订单簿；市场 WebSocket 订阅完整快照与价格档位增量，页面通过本地 SSE 接收更新。
- 每 10 秒发送上游心跳，失联后重连并等待完整快照再应用增量。增量按时间戳处理，零数量删除对应价位。
- 实时连接正常时约每 15～18 秒重新校准完整快照；断线时回退为每 3 秒轮询。请求在进行中时不会重叠发起，超时和退避会使异常期间间隔变长。页面显示当前方式、更新时间与异常状态。
- 超过 30 秒未核验的数据会标记过期。连续 WebSocket 的有效心跳会核验已初始化、没有错误的订单簿，安静市场不会仅因没有价格变动而被误报过期；价格更新时间与核验时间分开记录。断线或失败时保留旧数据并标记错误，等待完整快照恢复。

这是当前订单簿监控，**不包含历史深度回放、自动下单或告警通知**。上游标记已结束或已关闭的比赛，以及已关闭盘口自动隐藏；全部目标盘口均关闭的比赛也不再展示。进行中或暂时暂停接单的比赛继续保留，不能仅因开赛时间已过或没有报价就判断结束。赛程每分钟刷新，收到结束状态后自动从列表和统计中移除；过去的订单深度无法由实时接口恢复。

## 网络与云环境

需要 HTTPS 访问 `gamma-api.polymarket.com`、`clob.polymarket.com`，以及 WebSocket 访问 `ws-subscriptions-clob.polymarket.com`。安装依赖需要 `registry.npmjs.org`。遵循环境注入的 `HTTPS_PROXY` / `HTTP_PROXY` 和 CA 信任配置，不关闭 TLS 验证。公开行情接口不需要密钥。

云环境任务已隔离，直接使用现有 `/workspace/pol-NBA` checkout，不创建额外 Git worktree。依赖文件可通过环境快照保留，服务进程需要每次任务重新启动。环境设置中的安装脚本与启动说明用于复现配置；保存草稿与发布环境是两步，保存本身不会启动进程。

`GET /api/health` 返回服务、数据模式和上游状态；HTTP 200 仅表示服务可响应，真实行情还要确认 `mode=live`、`upstream=live`。`GET /api/state` 返回赛程、订单簿、更新时间及 WebSocket 状态；`GET /api/stream` 提供 `state` SSE 事件。`POST /api/settings` 可切换 `range` 和 `timezone`，设置作用于整个本地进程、重启后恢复默认。

接口依据与字段说明见 [docs/api-notes.md](docs/api-notes.md)。

## 皇冠登录与只读采集

主页面顶部的“皇冠配置”可启动本项目独立的皇冠登录窗口。后端通过一次只读 `mem_online` 检查后，将会话加密保存在本机；macOS 的加密密钥放入系统钥匙串。此流程不连接 HD-ps38。登录会话保存不代表比赛和盘口字段映射已验证，未审核的采集配置仍会被拒绝。

已接入今日与早盘 NBA 列表、单场全场独赢及主/附加让分和总分。同场同分值的皇冠水位显示在 Polymarket 报价下方，按球队和让分方向对应；半场、单节、关闭或过期盘口不参与有效比较。水位变化保存历史快照，轮询期间保留仍新鲜的上轮报价，最新响应中已消失的旧线立即退出比较。

默认每个请求至少间隔 500 毫秒，一轮结束后等待 10 秒；本机 14 场比赛实测约 18 秒一轮，实际速度取决于比赛数量、网络与重试。私有配置位于 `.local/crown/live-config.json`，每轮自动重新读取，登录会话、历史数据库和本机捕获不提交到仓库。

请阅读 [真实字段与未验证项](docs/crown-field-mapping.md) 和 [本地安全接入说明](docs/crown-setup.md)。配置示例 `config/crown.example.json` 保留未知字段和证据为空的安全默认值。
